# 📋 Finance Tracker - Повний План Розробки

---

## 🎯 Загальний Опис

**Концепція:** Local-first PWA додаток для персонального трекінгу фінансів без реєстрації в першій версії.

**Ключові принципи:**

- Всі дані зберігаються локально в браузері (IndexedDB)
- Офлайн-first підхід з повною функціональністю без інтернету
- Швидкість роботи на рівні нативних мобільних додатків
- Можливість встановлення як PWA
- Закладений фундамент для майбутньої синхронізації та авторизації

## 🗄️ База Даних (IndexedDB)

### Таблиці (Object Stores)

#### 1. **accounts** (Банківські рахунки)

- Поля: id, name, balance, currency, color, icon, createdAt, updatedAt, deletedAt
- Індекси: by-currency, by-deleted
- Soft delete для збереження історії транзакцій

#### 2. **transactions** (Транзакції)

- Поля: id, type, amount, currency, date, fromAccountId, toAccountId, categoryId, tags[], description, isSalary, isRefund, refundCategoryId, debtAccountId, deletedAt, version, syncedAt, createdAt, updatedAt
- Індекси: by-date, by-account, by-category, by-type, by-tags (multiEntry), by-deleted
- Типи: expense, income, transfer, debt_payment, debt_return
- Version field для conflict resolution при синхронізації

#### 3. **categories** (Категорії)

- Поля: id, name, color, icon, isDefault, deletedAt, createdAt
- Індекси: by-deleted
- isDefault = true для захисту від видалення базових категорій

#### 4. **tags** (Теги)

- Поля: id, name, usageCount, createdAt
- usageCount для автокомпліту популярних тегів

#### 5. **currencies** (Валюти)

- Поля: code (UAH, USD, EUR...), name, symbol, isDefault
- Підтримка 7 валют у v1: UAH, USD, EUR, GBP, CHF, CAD, AUD

#### 6. **salaryPeriods** (Зарплатні періоди)

- Поля: id, startDate, salaryTransactionId, createdAt
- Індекси: by-date
- Автоматичне створення при транзакції з isSalary=true
- Кінець періоду = startDate наступного періоду - 1 день

#### 7. **exchangeRates** (Курси валют)

- Поля: id (формат: "2025-01-22-USD-UAH"), date, from, to, rate, fetchedAt
- Індекси: by-date
- Історичні курси для точної конвертації старих транзакцій

#### 8. **user** (Користувач)

- Поля: id ("current"), isGuest, defaultCurrency, email (для v2), createdAt
- Single record для поточного користувача

### Міграційна Система

- Версіонування бази даних
- Послідовне виконання міграцій
- Збереження старих даних (IndexedDB не має ALTER TABLE)
- Нові поля додаються як optional в TypeScript
- Rollback неможливий (обмеження IndexedDB) - тому обов'язкове тестування

### Стратегія Soft Delete

- deletedAt = 0 → активний запис
- deletedAt = timestamp → м'яко видалений
- Збереження видалених рахунків для консистентності історії
- UI warning "\_deletedAccountId" для транзакцій з видалених рахунків
- Можливість відновлення

## 🎯 Основні Функції (Features)

### 1. Банківські Рахунки

**Можливості:**

- Створення рахунку з назвою, валютою, початковим балансом
- Кастомізація кольору та іконки
- Відображення поточного балансу
- М'яке видалення (зберігає історію транзакцій)
- Множинні рахунки в різних валютах

**Бізнес-логіка:**

- Баланс автоматично оновлюється при транзакціях
- При видаленні рахунку - транзакції зберігаються з міткою "\_deletedAccountId"
- Можливість відновлення видаленого рахунку

### 2. Рахунки Боргу

**Типи:**

- "Я винен" - борг зменшується при виплаті
- "Мені винні" - борг зменшується при поверненні

**Логіка "Мені винні":**

- При транзакції повернення: +300₴ на банківський рахунок, -300₴ від боргу
- Борг: 1000₴ → Повернення 300₴ → Залишок боргу: 700₴
- Транзакція рахується як income

**Логіка "Я винен":**

- При виплаті боргу: -300₴ з банківського рахунку, +300₴ до боргу (зменшення)
- Борг: -1000₴ → Виплата 300₴ → Залишок боргу: -700₴
- Транзакція рахується як expense

### 3. Транзакції

**Типи транзакцій:**

**a) Expense (Витрата)**

- Списання з банківського рахунку
- Обов'язково: категорія
- Опціонально: теги, опис
- Відображається в статистиці витрат

**b) Income (Дохід)**

- Додавання на банківський рахунок
- Прапорець "Це зарплата" → автостворення salary period
- Варіант "Повернення" → вибір категорії → віднімання від витрат категорії
- Відображається в статистиці доходів

**c) Transfer (Переказ)**

- Між власними рахунками
- НЕ впливає на статистику витрат/доходів
- Оновлює баланси обох рахунків
- Враховує міжвалютну конвертацію

**d) Debt Payment / Debt Return**

- Спеціальні транзакції для рахунків боргу
- Оновлюють борг та банківський рахунок одночасно

**Поля транзакції:**

- Дата та час
- Сума та валюта
- Рахунок джерела / призначення
- Категорія (для expense/income)
- Теги (множинні)
- Опис
- Прапорці: isSalary, isRefund

### 4. Категорії

**Функціонал:**

- Дефолтні категорії (не можна видалити)
- Додавання кастомних категорій
- Кольорове кодування
- Іконки для швидкого розпізнавання
- М'яке видалення (зберігає історію)

**Приклади дефолтних категорій:**

- Їжа та продукти
- Транспорт
- Житло
- Розваги
- Здоров'я
- Освіта
- Одяг

### 5. Теги

**Призначення:**

- Деталізація витрат (наприклад "кава", "таксі", "Netflix")
- Автокомплітер з найпопулярнішими тегами
- usageCount для ранжування
- Фільтрація статистики по тегах
- Множинні теги на одну транзакцію

### 6. Валюти

**v1 підтримка:**

- UAH (гривня) - дефолт
- USD (долар США)
- EUR (євро)
- GBP (фунт стерлінгів)
- CHF (швейцарський франк)
- CAD (канадський долар)
- AUD (австралійський долар)

**Конвертація:**

- Курси отримуються з API центральних банків
- Динамічна конвертація при відображенні
- Збереження історичних курсів для точності
- Дефолтна валюта для зведених звітів

## 📊 Аналітика та Звіти

### 1. Статистика Витрат від Обраної Дати (Ключова Фіча)

**Концепція "Зарплатні Періоди":**

- Користувач отримує зарплату 27 числа → встановлює цю дату як початок періоду
- Наступна зарплата 20 числа → автоматично закриває попередній період
- Кінець періоду = дата наступної зарплати - 1 день

**Режими перегляду:**

- **По зарплатам** - останні 12 зарплатних періодів
- **По місяцям** - звичайні календарні місяці
- **По тижнях** - останні N тижнів
- **По кварталам** - квартальна розбивка
- **По роках** - річна статистика
- **Кастомний період** - вибір дат вручну

**Відображення:**

- Загальна сума витрат за період
- Розбивка по категоріях
- Порівняння з попередніми періодами
- Тренди (зростання/спадання)

### 2. Витрати по Категоріям

**Можливості:**

- Список категорій з сумами витрат
- Відсоткове співвідношення
- Кругова діаграма (pie chart)
- Стовпчаста діаграма (bar chart)

**Фільтри:**

- Діапазон дат (range picker)
- Виключення категорій зі статистики
- Фільтр по тегах
- Режими перегляду: зарплати, місяці, квартали, роки, тижні

**Деталізація:**

- Клік на категорію → список транзакцій
- Показ повернень (refunds) окремим рядком
- Нетто витрати = витрати - повернення

### 3. Динаміка Загального Балансу

**Відображення:**

- Сумарний баланс всіх рахунків (в дефолтній валюті)
- Лінійний графік за останній рік
- Точки зарплат на графіку (якщо є salary periods)

**Фільтри при розгортанні на весь екран:**

- По зарплатних періодах
- По місяцях
- По днях (детальний)
- По тижнях
- По кварталах

**Інтерактив:**

- Виключення окремих рахунків з графіку
- Скролінг для перегляду історії
- Zoom in/out для деталізації

### 4. Історія Транзакцій

**Базовий список:**

- Хронологічний порядок (новіші зверху)
- Групування по датах
- Колір категорії для швидкого розпізнавання
- Іконки типів транзакцій

**Пошук:**

- По назві/опису транзакції
- Миттєвий результат (без затримки)

**Фільтрація:**

- **По рахунках** - можливість виключити рахунки з вибірки
- **По датам:**
  - По зарплатних періодах
  - Цей місяць
  - Минулий тиждень
  - Минулий місяць
  - Кастомний діапазон
- **По тегах** - множинний вибір
- **По категоріях** - виключення/включення категорій (дефолт: всі)

**Сортування:**

- По даті (ascending/descending)
- По сумі (від меншої до більшої / навпаки)

**Пагінація:**

- Підвантаження при скролі (infinite scroll)
- Віртуалізація списку для продуктивності
- Показ 50 транзакцій, потім підвантаження

## 🔄 State Management Стратегія

### Глобальний Context

**GlobalProvider:**

- Користувач (user)
- Дефолтна валюта (defaultCurrency)
- Онлайн статус (isOnline)
- Налаштування теми (theme)

**Доступ через useGlobalContext():**

- Всі дочірні компоненти мають доступ
- Рідко змінюється → мало ре-рендерів

### Feature Contexts (Опціонально)

**AccountsContext:**

- Список рахунків
- CRUD операції

**TransactionsContext:**

- Список транзакцій (з фільтрами)
- CRUD операції

**Альтернатива:** Custom hooks без contexts (легше для невеликого проєкту)

### Custom Hooks Pattern

**useAccounts():**

- Стан: accounts[], isLoading
- Методи: createAccount, updateAccount, deleteAccount
- Прямий зв'язок з IndexedDB

**useTransactions():**

- Стан: transactions[], isLoading
- Методи: createTransaction, updateTransaction, deleteTransaction
- Optimistic updates

**useCategories(), useTags(), useCurrencies():**

- Аналогічна структура

**useAnalytics(filters):**

- Обчислення статистики на основі transactions
- Мемоїзація для продуктивності

### Event-Driven Communication

**Custom Events для міжфічової комунікації:**

- `accounts-changed` → оновити баланс в UI
- `transaction-created` → оновити графіки
- `category-updated` → оновити кольори в списках

**window.dispatchEvent() / window.addEventListener()**

## 🌐 PWA (Progressive Web App)

### Service Worker

**Стратегії кешування:**

- **NetworkFirst** - сторінки, API (спробувати мережу, fallback на кеш)
- **CacheFirst** - статичні ресурси (іконки, шрифти)
- **StaleWhileRevalidate** - зображення, CSS, JS

**Офлайн fallback:**

- Всі сторінки працюють без інтернету
- IndexedDB доступна завжди

### Manifest

**Метадані:**

- Назва додатку
- Іконки (8 розмірів: 72x72 до 512x512)
- Theme color
- Background color
- Display mode: standalone

**Можливість встановлення:**

- iOS: "Додати на головний екран"
- Android: автоматичний prompt
- Desktop: встановлення через Chrome

### Online/Offline Індикатор

**Компонент OnlineStatus:**

- Показ при зміні статусу
- Автоматичне зникнення через 3 сек (якщо онлайн)
- Залишається, якщо офлайн

**Візуальні індикатори:**

- Badge з іконкою Wi-Fi / Wi-Fi Off
- Зелений (онлайн) / Червоний (офлайн)

### Install Prompt

**Компонент InstallPrompt:**

- Показ через 10 секунд після першого візиту
- Можливість відхилення (зберігається в localStorage)
- Не показується, якщо вже встановлено

**Переваги встановлення:**

- Швидкий доступ з home screen
- Повноекранний режим
- Робота офлайн

### Background Sync (Підготовка для v2)

**Концепція:**

- Реєстрація sync події при офлайн
- Автоматична синхронізація при поверненні онлайн
- Service Worker викликає sync handler

## 🔐 Майбутня Синхронізація (v2)

### Архітектурний Фундамент (v1)

**Version field в кожному записі:**

- Для conflict resolution
- Інкрементується при кожному update

**syncedAt timestamp:**

- Визначення, що потрібно sync
- null = ще не синхронізовано

**Soft Delete підтримка:**

- deletedAt для tombstones
- Синхронізація видалень між девайсами

### Sync Стратегія (v2)

**Last-Write-Wins з версіонуванням:**

- Порівняння updatedAt timestamps
- Переможець = найсвіжіший запис
- Version інкремент для відстеження конфліктів

**Запобігання конфліктам:**

- Sync при відкритті app
- Sync кожні 30 секунд (якщо онлайн)
- Конфлікти рідкісні (single-user, рідкий multi-device)

**Мануальне вирішення:**

- Користувач просто видаляє помилкову транзакцію
- Видалення автоматично sync

**Уникнення CRDT:**

- Занадто складно для цього use case
- Overkill для single-user app
- Last-Write-Wins достатньо для 99% сценаріїв

### Remote Database Interaction

**Виключно через IndexedDB:**

- Remote DB працює як replica
- Синхронізація в фоні
- Користувач завжди взаємодіє з локальною DB

**Consistency:**

- Eventually consistent
- Conflict resolution при sync
- Atomic operations на рівні транзакцій

## 🔑 Майбутня Авторизація (v2)

### Фундамент в v1

**User таблиця:**

- id: "current"
- isGuest: true (в v1)
- email: null (додасться в v2)

**Auth готовність:**

- User entity вже існує
- Легко додати email/password поля
- Sync прив'язується до userId

### Auth Flow (v2)

**Реєстрація:**

- Email + password
- Створення account на сервері
- Upload локальних даних

**Логін:**

- Email + password
- Download даних з сервера
- Merge з локальними (якщо є)

**Guest → Registered:**

- Опція "Зареєструватися" в налаштуваннях
- Збереження всіх локальних даних
- Асоціація з новим account

## 🧪 Тестування та QA

### Тестові Сценарії

**Створення та видалення:**

- Створити рахунок → баланс оновлюється
- Видалити рахунок → транзакції зберігаються
- Відновити рахунок → все працює

**Транзакції:**

- Expense → баланс зменшується, категорія оновлюється
- Income → баланс збільшується
- Transfer → обидва рахунки оновлюються, статистика не змінюється
- Refund → віднімається від витрат категорії

**Валюти:**

- Створити транзакцію в USD → конвертація в UAH для статистики
- Курс зберігається для історії

**Офлайн:**

- Створити транзакцію офлайн → все працює
- Повернутися онлайн → (в v2) синхронізація

**PWA:**

- Встановити додаток → іконка на home screen
- Закрити браузер → відкрити додаток → всі дані на місці

### Performance Metrics

**Цілі:**

- Створення транзакції < 100ms (UI response)
- Завантаження історії 1000 транзакцій < 500ms
- Scroll 60 FPS (віртуалізація)
- Lighthouse PWA score: 100/100

### Browser Compatibility

**Підтримка:**

- Chrome/Edge 90+ (основний таргет)
- Safari 14+ (iOS)
- Firefox 88+

**Критичні APIs:**

- IndexedDB (всі сучасні браузери)
- Service Worker (PWA)
- localStorage (fallback)
